Does cache (prompt caching) hit count toward your limit? Caching billing rules

Prompt Caching is an optimization where repeated prompt prefixes are cached, and subsequent hits cost much less — but the usage is still counted.

How cache hits are billed

When the first N tokens of a prompt exactly match cached content, the hit portion is typically billed at 10%-25% of the normal price (discount varies by provider). Unmatched portions are billed at full price.

Does it count toward message limits

In the web version, cache hits don't affect message count (still one message = one quota). In the API, cached-hit tokens count toward usage at the discounted rate, but don't reduce message-turn count.

How to improve cache hit rate

  • Place fixed system prompts at the start of requests
  • Keep context structure stable, avoid changing prefixes frequently
  • Be aware of cache TTL (usually 5 min - 1 hour)
  • Reuse the same prefix structure in long conversations

FAQ

How much can caching save?

For workloads with large repeated system prompts, cache hits can save 50%-90% of token costs, depending on hit rate and discount.

Does caching affect answer quality?

No. Caching only affects billing and speed — model output quality is identical to uncached requests.
